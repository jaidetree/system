#+title:    :editor lisp-state
#+subtitle: Spacemacs-style structural sexp editing, as its own evil state
#+created:  September 15, 2026

* Description :unfold:
Adds an evil "lisp state" for structural sexp editing (slurp, barf, raise,
convolute, splice, wrap, transpose, ...) with Spacemacs-style mnemonics
under =SPC k=. Any =SPC k= command enters lisp state; ESC returns to
normal state; =SPC k .= toggles the state manually from anywhere.

Built on the Spacemacs =evil-lisp-state= package
([[https://github.com/syl20bnr/evil-lisp-state]]). =setup.el= patches two
things upstream hard-codes for Spacemacs/undo-tree: undo/redo now dispatch
to whatever backend is actually available (undo-fu, undo-tree, or plain
undo), and the =.= toggle is reachable from normal state, not just from
inside lisp state.

Lisp state also gets its own cursor color, its own doom-modeline face, and
its own doom-modeline icon, so it reads as a first-class evil state the
same way normal/insert/visual do, rather than falling into doom-modeline's
generic "user state" styling.

** Hacks
- =setup.el= rebinds =u=, =C-r=, and =.= after loading evil-lisp-state,
  since upstream hard-codes =u=/=C-r= to =undo-tree-undo=/=undo-tree-redo=
  (both directly in =evil-lisp-state-map= and, via
  =evil-lisp-state-commands=, under =SPC k= in
  =evil-lisp-state-major-mode-map=) and only binds the =.= toggle inside
  =evil-lisp-state-map=, not reachable from normal state. See
  =+lisp-state-undo=/=+lisp-state-redo= and their =-backend= counterparts.
- =setup.el= remaps the modeline's =doom-modeline-evil-user-state= face to
  a dedicated =+lisp-state-modeline-face= while lisp state is active, via
  =face-remap-add-relative= on =evil-lisp-state-entry-hook= /
  =evil-lisp-state-exit-hook=. This works around =doom-modeline--evil=
  (in doom-modeline-segments.el) hard-coding any evil state it doesn't
  recognize by name to that fallback face; the function is a =defsubst=
  inlined into the byte-compiled modeline segment at package build time,
  so it can't be overridden by redefining or advising it at runtime.
- =setup.el= also advises =doom-modeline--modal-icon= (a plain =defun=
  that =doom-modeline--evil= calls out to, and so — unlike
  =doom-modeline--evil= itself — can be advised) to swap in an =L= icon
  in place of the generic "user state" glyph, scoped to only fire when
  the rendering buffer's =evil-state= is =lisp=.

* Installation
Enable this module in your =doom!= block:

#+begin_src emacs-lisp
:editor
lisp-state
#+end_src

/This module has no external requirements./

* Usage
Bound under =doom-leader-key= + =k= (=SPC k= with Doom's default leader;
follows =doom-leader-key= if you've changed it). Any command below enters
lisp state (per =evil-lisp-state-enter-lisp-state-on-command=); =SPC k .=
toggles it explicitly; ESC returns to normal state.

| Key         | Action                                     |
|-------------+---------------------------------------------|
| ~SPC k s~   | forward slurp                              |
| ~SPC k S~   | backward slurp                             |
| ~SPC k b~   | forward barf                               |
| ~SPC k B~   | backward barf                              |
| ~SPC k r~   | raise expression                           |
| ~SPC k w~   | wrap expression with parens                |
| ~SPC k W~   | unwrap expression                          |
| ~SPC k t~   | transpose expression                       |
| ~SPC k c~   | convolute expression                       |
| ~SPC k u~   | undo (backend-aware)                       |
| ~SPC k C-r~ | redo (backend-aware)                       |
| ~SPC k j/k~ | next closing / previous opening paren      |
| ~SPC k ds~  | delete symbol                              |
| ~SPC k dw~  | delete word                                |
| ~SPC k dx~  | delete expression                          |
| ~SPC k .~   | toggle lisp state                          |

See the full command table in [[https://github.com/syl20bnr/evil-lisp-state/blob/master/evil-lisp-state.el][evil-lisp-state.el]]
for the rest of the bindings.

* Configuration
The major modes the =SPC k= prefix is active in are set in =setup.el=
via =evil-lisp-state-major-modes=: =emacs-lisp-mode=, =lisp-interaction-mode=,
=lisp-mode=, the Clojure family, =janet-mode=, =racket-mode=,
=scheme-mode=, and =fennel-mode=.

* Testing
=test/lisp-state-test.el= is a batch-mode integration test that loads the
exact code =config.el= runs (via =setup.el=) and asserts every key
binding, the cursor color, and the modeline face-remap lifecycle against
the installed package:

#+begin_src sh
emacs -Q --batch -l ~/.config/doom/modules/editor/lisp-state/test/lisp-state-test.el
#+end_src

It prints ~lisp-state OK~ and exits 0 when the bindings are live.
